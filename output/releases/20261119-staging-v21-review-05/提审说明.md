## 代码审查和回归

| 审查范围 | 处理与验证 |
| --- | --- |
| 续局与账号隔离 | 合并回前台和联网恢复，首页使用同一续局链路。会话代次变化时重新查询同一局一次。保存旧账号迟到的恢复回执和 401 后跨账号重试均已拦截。 |
| 开局和存档 | 登录返回匹配的开局协议时省掉一次健康查询，旧后端继续验证完整能力。完全相同的确认点直接响应，时钟只允许前进；新操作仍须验证会话、动作和奖励凭据。 |
| 道具和奖励 | 用同一入口处理锤子和魔法棒。V20 及以上保留锤子分享、魔法棒视频和各五次补给；奖励倒计时保留在当次请求中。 |
| 包体与界面 | 归档 12 个旧连击音频和复活卡原图，保留当前 v4 声音。复活卡运行贴图使用 768×512，商城按需加载。移除已停用的 UI 参数、旧图标代码和商城旧商品分支。 |
| 既有玩法 | 保留难度爬坡和减压规则、计分波段、道具连锁、闪电点击、普通救场与免费暖心提示。实际 V15、V20、V21 微信编译包连接隔离后端，通过开局、存档、续局、重放和幂等结算。 |

本地 263 项客户端与 80 项后端测试通过。TypeScript 含未使用检查通过。Web 与微信构建、GM 隔离、CDN 字节核对通过。三种屏幕尺寸的 Cocos 浏览器验收覆盖正常本机存档、仅云端存档、两种本机核验失败、商城卡图和两种补给。广告和分享使用 Web 模拟回调，后端使用真实本地 API。

## 提审路由

微信包的实际入口在载入游戏模块前固定使用 Staging。对微信环境为开发、体验、正式和环境识别抛错四种情况运行了编译包路由校验。该候选可用于审核隔离。正式发布窗口仍需准备正式路由产物，按项目发布约定协调前后端。
