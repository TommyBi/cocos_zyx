# 爽感链路与动态难度：补充评估

> 后续已完成 V2 实现与验证，以 `docs/game-feel-v2.md` 和最新变更日志为准；下文保留评估时的方案。

日期：2026-11-11。本文件以用户最新补充为准：先调整局内手感，权益总量与折算比例后置；本轮评估不涉及线上。此次完成代码核对和隔离模拟，尚未实现下述玩法改动。

## 目标修订

不再将“前十五步每次单排消除”视为完整目标。目标是连续且有变化的反馈：

容易识别的移动 → 双排或多轮掉落消除 → 生成炸弹 → 主动引爆/满行触发/被其他炸弹波及 → 再次爆破与掉落消除 → 获得下一次可用道具。

玩家在友好阶段积累的炸弹可以带入难度上升阶段，帮助消化变化。单局连锁的触发、时长和道具存量应可控；可兑现权益的总额度和折算率在手感稳定后统一调整。原报告的安全发现仍是代码事实，但不作为本轮手感方案的前置实施范围。

## 当前断点与补充验证

1. 满行消除直接移除所有该行色块，未引爆其中的炸弹。受控棋盘中，炸弹随满行消失，但位于其应有爆炸范围内的邻块仍存在。
2. 爆炸范围内的另一枚炸弹只是被移除，不产生二次爆炸。受控棋盘中，被第一枚炸弹波及的第二枚消失，其独立爆炸范围内、但不在第一枚范围内的目标仍存在。
3. 引爆本身不构成满行成功，因此若后续没有满行，操作结束后 combo 归零。受控棋盘将 combo 设为真实成功后的 3，再引爆且无满行，最终为 0。
4. 现有奖励在各次稳定结算时生成，之后本次操作还可能自动补排、继续消除；应将“道具奖励发放点”统一到整个玩家操作最终结束，保证新生成的道具留给下一次互动。

源码：`ZyxGameModule.ts` 的 `eliminateFullRows`、`detonateBomb`、`resolveBoard`，以及 `ZyxGame.ts` 的 `resolveStableBoard`、`appendNextRowAndResolve`。

补充模拟仅在临时编译副本中把炸弹门槛从 combo=4 改为 3，没有改棋盘生成、连锁或续连规则。教学局每种方案 1,000 组分布式种子，最多 30 次自由操作，分别测试“优先提示解”和“优先炸弹”两种简单策略：

| 指标 | 4 combo 给炸弹 | 3 combo 给炸弹 |
| --- | --- | --- |
| 教学结束拥有炸弹 | 0/1000 | 1000/1000 |
| 第一次自由操作有一格直消解 | 16.0% | 20.3% |
| 优先炸弹策略的炸弹操作未接上满行 | 934/988 | 2075/2196 |
| 优先炸弹策略在自由阶段内达到 Perfect | 29/1000 | 21/1000 |

这些是现有生成器和指定策略的局部实验，不是用户表现、最优策略或新方案收益预测。它们说明：门槛下放能保证更早拿到第一枚，但单独下放无法补齐链路；还应修改触发、续连、布局与生成时机。

结果：`bomb-threshold-results.json`、`bomb-behavior-proof.json`。阈值实验可在仓库根运行 `node output/difficulty-analysis-2026-11-11/evaluate-bomb-threshold.cjs`；只写临时编译目录并向标准输出输出结果。

## 建议规则

### 将三种爽感分别记录

- combo：跨玩家操作的连续成功，沿用现有最高五倍。
- 双排/多排：同一轮同时消除至少两排。
- 连锁：同一次玩家操作内，首次消除后因爆炸或掉落再次消除，可能有多轮。

双排和连锁分别加强演出，不能仅靠 combo 字样表达。单次内部多轮消除不反复增加跨操作 combo；演出强度可以递进，分数倍率仍封顶。

### 炸弹提前，并真正接入消除

- 将每段连消首次给炸弹的门槛由 4 combo/Great 下放到 3 combo/Good；第四、第五次不因为处于该连消段而重复领取同一里程碑。
- 一次操作累计清掉至少两排，继续给一枚；既包含同时双排，也包含两次掉落消除。同次操作同时达到三连与双排，允许两条不同奖励各给一枚。
- 炸弹被普通满行消除、主动点击或其他炸弹波及时都引爆。被波及的旧炸弹允许继续连锁。
- 有效爆破可保留已有 combo；爆破本身不凭空推进 combo，后续若真的产生满行，按一次操作最多推进一次的规则处理。没有满行也没有有效爆破的普通失败操作仍会断连。
- 保留当前“炸弹附着普通横块”的玩法，不引入更多道具品种，先做好这一条链。

### 连锁边界

- 每次玩家操作有独立结算上下文。色块和炸弹按唯一 ID 去重：每块最多移除、收集一次，每枚炸弹最多引爆一次。
- 本次操作中先结算进入操作前已有的炸弹、自然消除、掉落、自动补排；所有次生炸弹在整个操作稳定后统一生成，不能在出生的同一步继续被触发。
- 同一双排/连锁奖励按完整玩家操作累计，只发一次；三连里程碑同样只发一次。因此两个来源叠加时，每次操作最多两枚，避免补排多次重复发奖。
- 场上存量上限第一版建议三枚，作为待测参数；满额不追加新炸弹，现有炸弹保持可用。评估这个限制是否影响消除回报，再决定调整。
- 对自动补排也设明确预算；预算用尽时允许结束于较少占用行，下一次互动再恢复供给，避免无人操作时无限补排、消除。具体预算需结合模板测定。
- 增强视觉表现时记录本次动画总时长，后几轮可适度加快，不要把连续爽感变成长时间等待。

这种边界允许“本步消除产道具、下一步道具再产连锁”，也允许旧炸弹之间同一步连锁，但不会形成新道具在同一步持续自我复制。

## 动态难度方案

使用“逐渐提高并最终封顶的阶段基准 + 当前棋盘的有限帮助”。只看棋盘危险就无限放松，会抹平后期梯度；只看步数则无法照顾当前盘面。

盘面输入优先使用能确定性重放的事实：最高堆高及上升趋势、封闭空洞、容易成功的移动数量/比例、位移距离、双排和二次掉落机会、近期未消除次数、已有炸弹数量和实际覆盖能力。相同高度但有两枚好位置炸弹，与没有炸弹、没有直接解的棋盘，压力不应按同一数值处理。

在稳定棋盘上评估；已经展示的下一排作为固定约束，调整尚未展示的后续行。生成时模拟真实满行、爆炸、掉落与补排，而不是只判断下一排能横移。先用便宜指标筛候选，再对少量候选模拟后续一两步；在低端设备测量耗时，避免无上限搜索。

典型决策：

| 当前状态 | 后续出排方向 |
| --- | --- |
| 棋盘太空、缺少支撑 | 补容易整理的支撑结构，为下一次双排或掉落连锁蓄势 |
| 有一处简单消除但反馈偏单薄 | 保留这处容易解，安排后续掉落再次补满 |
| 多次普通单排、近期没有高点 | 增加双排或连锁机会，不必提高资源出现密度 |
| 堆高上升、容易解少、没有可用炸弹 | 减少封闭空洞，提供容易识别的解压机会 |
| 手中已有合适炸弹 | 保留合理受益区域，让爆炸能带动掉落；不自动把棋盘加难抵消奖励 |
| 进入较后阶段 | 逐渐减少明显解、增加规划深度，帮助限制在该阶段范围内 |

友好阶段先以 30–40 次普通移动作为观察窗口，辅以实际体验是否发生：见过 Perfect、双排/掉落连锁和一次炸弹使用。它是原型参数，不是已经验证的最佳时长。普通移动推进阶段；主动引爆、连锁、自动补排不加速升难。后续阶段基准缓慢提高并封顶，局部帮助不重置阶段。已经送给玩家的炸弹必须能真实抵消一部分新增压力。

建议原型阶段每十次普通移动的观察目标为：8–9 次有消除，其中约三次出现双排或多轮连锁，并有数次道具获得/使用。该目标是待调参数；重点是连续反馈的密度和高点，不能仅增加单排次数。最初十几次仍应有容易连续成功的路径，但友好体验不在第十五次突然结束。

## 放出后置，但计数保持正确

暂不调整每豆折算、日总额或权益政策。准确记录唯一表情块收集、每分钟收集量、每次普通移动引发的自动补排量、连锁深度、炸弹产生/消耗和阶段压力。后续用稳定手感下的这些分布校准总放出与折算率。

爆炸轮数、combo 或多个重叠范围不重复计算同一表情块；客户端展示与服务端重放使用相同规则。上述数据正确性和连锁边界属于玩法实现的基本约束，不必等经济调参。

## 建议实施顺序

1. 接通满行引爆、炸弹间连锁、爆破续连及稳定后产道具，并同步双端事件语义。
2. 下放至三连给炸弹，加入单操作奖励去重和场上存量约束。
3. 调整生成器，使双排与二次掉落机会持续出现；用当前盘面和炸弹能力评估压力。
4. 加长并丰富友好阶段，再调中后期递增与封顶。
5. 在真人手感和多种策略模拟都稳定后，校准放出总量与折算。

一般的动态难度研究也将调整动作和干预成本、频次结合，而非只按当前失败次数反复送帮助，参见 [Hunicke 与 Chapman 的原始研究](https://users.cs.northwestern.edu/~hunicke/pubs/Hamlet.pdf)。本文规则和数值均为针对本项目的建议。
