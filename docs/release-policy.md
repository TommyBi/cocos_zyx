# 提审与正式发布约定

2026-11-18，用户明确纠正发布时序。本文件覆盖历史文档中“提审前必须升级Production”的表述。

1. 新功能开发、验收与提审准备仅更新Staging；提交微信审核不是授权更新Production。
2. 审核访问新功能应隔离到Staging。微信代码提审本身不决定后端地址，必须验证候选包的实际路由，不能把开发/体验版的验证当成审核路径已经验证。
3. 审核通过后，仍需用户明确决定正式上线。只有进入该正式发布窗口，才可协调配套Production后端和前端发布。
4. 正式上线前验证生产后端兼容仍在运行的旧客户端、未结算局和历史数据；新规则只对相应新版本生效。不能通过直接替换业务规则使旧客户端失效，也不能在新前端已经生效后才临时补后端。
5. 审核未通过、审核撤回或用户未决定上线，Production继续服务现有正式版本。独立生产热修复或数据修改仍须有针对该事项的授权。

当前事实（2026-11-18）：用户已报告前端审核通过并发布，随后明确授权后端Production升级。已完成 `20261118-production-api20-135431`，正式API20/V15/schema12，与Staging同一镜像，数据和旧局兼容验收通过。此前Production仍API18的记录为升级前状态。

当前代码CloudService.getApiBase仅按envVersion将develop/trial送Staging、release及获取环境异常送Production。尚无本候选审核链路的实测证据，不能断言审核访问必然是Staging，也不能据此要求提前升级Production。当前提审检查应解决该路由验证和隔离问题，而非修改生产环境。
