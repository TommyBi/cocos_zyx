# 开心豆收集进度 UI 概念

本轮只出两套 UI 设计图，不实现商城，不修改客户端或服务端经济规则。

## 用户给定规则

每消除 100 个带表情格子累计 1%；累计 10,000 个达到 100%，奖励 1 颗开心豆。完成 100% 后的奖励演出使用「开心豆 +1」。

## 共同展示建议

- 主信息为百分比，例如 37.26%；每个带表情格子对应 0.01%。整数部分最醒目，小数稍小，兼顾百分比辨识与逐次收集反馈。这是展示建议，未修改数值逻辑。
- 总进度条/环表达距离下一颗开心豆的整体进度；小字「集满100%得1颗」解释目标。
- 表情粒子汇入图标后，进度平滑推进约 0.3 秒；数字只在变化位轻微上滚，避免整个组件跳动。批量消除合并推进。
- 100% 时短暂定格，图标轻弹、金色柔光，显示「开心豆 +1」，再平滑进入下一轮进度；超过 100% 的进度应结转（待规则实现时确认细节）。
- 进度跨局保留、服务端结算与历史资产迁移尚未实现，后续规则开发时单独处理。

## 方案 A：得分下方居中

合并为宽奶油色 HUD。本局得分位于中轴，收集组件位于其正下方且共享中轴；最高分弱化在右上。开心豆图标、小数百分比与细条组合，形成从得分到收集目标的纵向阅读顺序。

## 方案 B：右上角独立收集卡

左侧得分卡沿用现有双列，右上独立奶油黄卡片。豆子头像配环形进度，右侧突出百分比，下方为奖励目标。数字与环形进度关联，保留现有操作视线与棋盘空间。

## 方案 B 二次优化：本局收获 + 下一颗进度

- 用户偏好 B，并明确一局可以获得多颗开心豆，需要持续看清本局已收获数量。
- 得分卡缩为约 28% 宽度，纵向显示本局得分和次要的最高分；右侧收集卡占约 70%，百分比成为最醒目的数字。
- 圆环内保留豆子图标，在底部叠加半透明暖棕徽标「本局 +3」，不遮挡表情；此数量为本局累计获得，不是总钱包余额，也不是本次消除的临时飘字。
- 百分比上方使用「下一颗」明确当前循环目标；「本局 +3 / 下一颗 37.26%」表示已获得 3 颗，正在积累第 4 颗。
- 满格自动获豆：本局 +3 / 99.98% → 本局 +4 / 100%（豆子轻弹、开心豆 +1）→ 本局 +4 / 0.02%（示例包含本次消除的进度结转）。数量只在获得整颗豆子时递增，平时只更新百分比和进度环。
- 产物：`option-b-v2-collection-goal.png`；内置 image_gen 提示词：`option-b-v2-prompt.txt`。仍仅为设计概念，未修改经济规则或游戏代码。

## 生成方式与提示词

使用内置 image_gen，输入用户截图作为风格与布局参考；两套均移除红色标注、教学遮罩与教学气泡，保留游戏软糖、奶油、暖棕线条的视觉语言。图片为概念设计，不代表已经落地。

完整提示词见 prompts.json。
