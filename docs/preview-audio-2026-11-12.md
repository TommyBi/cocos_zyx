# Codex 预览音乐重叠修订

> 后续现场排查已确认旧页面仍存在并在播放。本文的服务连接数不代表实际页面数，实际标签与音源结果以 `docs/actual-preview-audio-2026-11-12.md` 为准。

2026-11-12。本轮针对“Codex 右侧预览仍有两个声音”，补充跨页面控制。此前单页音源和生命周期验证无法证明多个预览之间互斥。

## 证据与原因

用户确认关闭右侧所有旧预览后声音全部停止。在两个隔离浏览器环境中复现：它们可以同时报告 visible、hasFocus=true，且各有一条正在运行的音乐，原来的焦点判断无法排除这种重叠。此复现与用户反馈一致；Agent 无法直接枚举右侧全部 WebView，未把浏览器模拟写作实际 Codex 试听。

## 实现与CR

- AudioManager增加独立的本地预览播放许可，失去许可后暂停音乐、停止效果音；focus、onShow和迟到的资源回执不能绕过它。微信和正式Web没有预览标记时照常运行。
- npm run serve:web改用 scripts/preview/server.cjs，默认7458端口。预览控制脚本在Cocos之前注入，各浏览器隔离环境通过同一本机服务交接音乐。请求方等待旧页暂停Cocos音频和原生AudioContext后才播放。
- 重开/点击使用唯一播放令牌，迟到回执不能撤销后续播放权；令牌包含服务会话随机数，重启不会复用旧令牌。
- 浏览器resume可能一直等待用户手势，因此恢复请求不能阻塞停声消息。浏览器禁用自动播放时，点击当前页解锁声音。
- 连接错误时客户端立即停声并发送独立HTTP回执。关闭WebView可能直接销毁JS而没有回执，服务端对已断开的连接等待250ms后回收播放权；该清理是故障兜底，不等同于已确认旧页静音。极端网络中断并同时冻结页面JS的情况不在本轮浏览器验收范围内。
- 所有预览协调脚本、演示夹具和本地API代理留在 scripts/，不进入Web/微信游戏构建。当前运行预览代理独立8094测试API，不修改原8080服务或原玩家数据。

## 验证

两个独立浏览器上下文：初次打开、新页接管、旧页focus/onShow、来回点击、关闭拥有播放权的页面、再次打开、刷新，8个阶段的底层正在运行循环音源总数均为1；另一个页面为暂停状态。没有页面异常。禁用自动播放策略下仍能完成交接，真实点击可恢复当前页音频。

此前14阶段单页生命周期回归仍通过：首页/局内各1条；暂停、静音、音量0、结算、加载和销毁均0条，前后台不能越过限制。

159项客户端和41项服务端测试全部通过；TypeScript、资源检查、Web构建、微信构建、GM隔离与主包预算通过。微信主包2,466,591字节（2.35MiB），home分包334,370字节，effects分包1,034,459字节，总代码包3,835,420字节；预览控制文件未打包。相比上一音乐候选主包增加261字节，没有新增图片或音频。
