# Codex实际预览音频排查订正

2026-11-12。用户再次反馈进局内仍听到局外音乐后，本轮直接读取当前聊天的 Codex IAB 标签与音频对象，而非使用服务连接数和独立浏览器代替实际预览。

## 确认的问题

IAB实际保留了10个游戏预览。我之前多次调用打开预览，没有复用或关闭已有标签，留下了多个仍在运行的游戏实例。旧标签5的music_main处于PLAYING且AudioContext为running，当前标签10的music_game也处于PLAYING且AudioContext为running。旧标签1/2/3/4/6也各有一条正在运行的局内音乐。旧标签7的首页曲所在Context已暂停，8/9无音轨。

服务端显示的1个连接只覆盖装有新协议的预览；旧版本没有这个连接，所以“连接数1”不能推断“实际只有1个页面”。先前让用户清理后就判断已清理完成，没有核对实际标签，是我的验证错误。

## 处理和复验

已通过浏览器控制直接关闭本任务创建的旧标签1至9，保留当前10。实际标签列表已核对只剩1个，没有再创建新预览。

在保留的真实预览中通过按钮执行：暂停→退出→结算→返回→首页→开始新局。最终有效复验的原生音源记录：

| 状态 | 登记音乐 | 底层正在运行音乐 |
|---|---|---|
| 局内 | music_game，ID8 | game，115.2秒，1条 |
| 暂停 | ID8，PAUSED | 0条 |
| 结算 | 无，ID -1 | 0条 |
| 首页 | music_main，ID9 | main，126秒，1条 |
| 首页进入局内 | music_game，ID10 | game，115.2秒，1条 |

最后一步中，126秒首页音源同时记录到stop与ended；新的115.2秒局内音源仍在运行。由此确认这个页面内的切换已停止首页音源；实际重叠的首页曲来自旧标签5。

音源记录钩子第一次写入时误将记录对象作为音源返回，造成诊断期间播放异常；已修正、清理失败实例并从头完成上述有效复验。临时诊断钩子已移除，当前页面仅保留正常music_game，未改动游戏正式源码来掩盖问题。

## 对先前改动的复查

- AudioManager将首页/局内/静音、暂停和前后台等播放许可集中控制，当前只有原生loop，没有ended回调另起一套循环。首页进入局内时调用stop终止旧ID，再启动新曲。实际预览已确认该路径。
- GameSettings和设置面板不再各自控制引擎；AssetLoader等待音频解码就绪，旧异步请求有代次检查。这些是上一轮的单页生命周期修复，不是本次遗留页面清理。
- 新增本机预览交接只控制加载过新脚本的页面，无法控制此前保留的旧版页面。不得再把新协议的连接数作为整个Codex浏览器的页面数。
- 没有为本次反馈继续叠加音频控制代码。问题处理是关闭由我遗留的旧运行实例，并订正预览和验收流程。后续优先复用现有游戏标签。

实际记录见“Codex实际音轨排查.json”，截图“Codex实际局内预览.png”。本轮没有改动游戏资产、API、微信包或线上服务；此前200项测试和包体数字属于上一轮代码验证，不代替本次现场排查。
