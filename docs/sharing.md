# 微信分享图

右上角「转发给朋友」以及体力、解压锤、魔法棒、救场、复活五个奖励分享点统一使用 `ShareReward.ts`。每次发起分享才随机选一套，标题与图片绑定，三个选项概率相同，允许连续抽到同一张。奖励规则继续沿用原有的前后台间隔判定。

| 图片 | 原图主文案（分享标题） | JPG 字节数 |
| --- | --- | ---: |
| 爆消爽感 | 这一拖，爽翻了！ | 82,443 |
| 绝境翻盘 | 快满了？一拖翻盘！ | 85,176 |
| 冲榜逆袭 | 边消边冲榜，下一名被我超了！ | 82,000 |

微信官方接口说明指定好友分享卡片按 5:4 展示，并允许网络图片路径：[官方 API 类型定义](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts)。本项目输出 500×400 的 JPG，单张目标上限 96 KiB；这是本项目的加载体积目标。原始 1024×1536 海报等比完整保留，左右以原图模糊背景补齐，避免裁掉标题与底部文字。

原图位于 `output/marketing/2026-11-05/`，压缩图、来源与内容哈希清单位于 `share-assets/20261112/`。运行时只编入 `assets/script/manager/ShareConfig.ts` 中的三组标题与 CDN URL，不导入图片资源。输出文件名包含内容哈希，避免微信/CDN 继续使用旧图缓存。

CDN 现有防盗链允许微信来源请求，无 Referer 抓图返回 403。游戏启动时通过 `wx.downloadFile` 预取三张图片并缓存临时路径，原生分享使用已下载文件，避免依赖微信卡片服务的匿名抓取。未预取完时，菜单分享使用官方支持的三秒内异步参数补齐；奖励分享先下载选中的图，成功拉起分享时才开始三秒奖励判定。下载失败不发奖励，下次可重试。未修改 CDN 防盗链配置。

更新流程：

```sh
python3 scripts/prepare-share-images.py
node scripts/publish-remote.js --share
npm run build:wechat
```

处理脚本同时更新 `ShareConfig.ts`；发布脚本严格校验三张图的哈希、字节数、尺寸声明与 URL，只上传清单内 JPG，禁止覆盖已存在的同名 OSS 对象，最后携微信 Referer 从 CDN 下载逐字节核对。原始海报与分享 JPG 均不进入微信主包、首页分包或音乐 Bundle。

微信构建在分包体积检查前无损压缩生成目录中的 PNG；只有像素、尺寸、ICC、gamma 与色度配置一致且文件更小时才替换。不重编码索引色或独立透明度图片。
