# 商城与快速挑战（2026-11-17更新）

首页右侧排行榜下方为「商城」。两张商品卡使用裁切的纵向滑动列表，保留奶油纸感、柔和色块和留白。按钮显示「兑换 + 价格 + 开心豆图标」，价格余额不足为红色、充足为绿色；名称、效果说明和库存分层展示。复活卡采用已认可的第二版二维手绘纸卡图，不在图标中嵌价格。

商城不再提供解压锤、魔法棒兑换；体力3豆兑换1点；体力图标为暖金色圆角闪电，完整笑脸位于中腰内，首页/商城/开局飞行共用。体力支持超过自然恢复上限，未满时兑换保留已积累的恢复时间。点击不足余额的兑换按钮不会发送扣款请求，会打开「开心豆不足」提示，可返回商城或快速开始挑战。快速挑战复用首页的服务端开局流程，体力不足时进入原补充体力弹窗；同一时间仅允许一次开局请求。首页开始按钮和快速挑战按钮上方都有每秒刷新的体力/恢复倒计时。

## 资产与操作

- `POST /shop/exchanges`：`actionId`、`item`（`stamina` / `reviveCard`）；体力3豆，复活卡25豆兑换1张，同事务扣款发货并持久化。忽略客户端价格与数量。余额不足不产生流水；同 ID 不同商品返回冲突。相同请求重试返回当前档案，不重复扣款。

## 复活卡规则

每局首次失败使用广告复活；再次失败有卡才提示消费一张额外复活，无卡直接结算。每局卡片只可使用一次，不因库存多而增加次数。扣卡、使用凭据与完整恢复棋盘由服务端同事务保存，最终结算逐条验证。结构10原地增加卡片库存，不重置旧玩家资产。详见 [复活卡设计与验收](revive-card-2026-11-17.md)。
- 客户端兑换前持久化 ID；结果不明保留请求并显示「继续确认」，确认前不发第二笔兑换。并发点击由界面与接口双层处理。关闭弹窗不取消已经发送的请求。
- `POST /games/tools/use`：当前 `roundId`、动作位置 `actionIndex`、道具与目标。V12服务端消费本局已领取资格并记录凭据（旧局仍按旧库存协议），客户端得到确认才改棋盘；网络结果不明冻结该动作，重试复用 ID 和目标。新局结算按操作位置、类型、目标逐条检查道具凭据，不能靠修改本地库存免费使用。
- `POST /games/tools/reward`：V12解压锤分享领取最多3次、魔法棒视频领取最多1次，领奖ID幂等。资格由`tool_transactions`绑定到该局，不写跨局库存，持有时不再领取；响应与续玩信息含`roundTools`。图标无持有显示加号，领取后显示1，使用达上限后遮暗。关闭获取或取消选择不消费。该回调目前仍属于客户端完成声明，**不等于接入广告平台服务端验签**，不能宣称已阻止伪造广告完成。后续若需真实广告收益，应补平台验证。
- 所有玩家写入推进 `assetRevision`。客户端忽略低版本及迁移前无版本的历史回执，防止旧结算余额覆盖消费、旧库存覆盖使用；开局返回最新权威档案，刷新不会补回已用道具。
- schema v8 原地增加 `hammer_count` / `wand_count` / `asset_revision`、`tool_transactions`，不重算原余额。历史本地道具不是可信建档来源，不自动上传；服务端初始库存为零。GM 专用工具同步现已包含道具，生产仍禁用 GM 路由。
- `game_rounds.tool_rules_version`：历史在途局为 0，新局为 1，只对新局强制使用凭据，避免旧补传因新增协议被拒绝。默认关闭旧协议新开局，防止直接报数领取旧制奖励；`ALLOW_LEGACY_ROUND_STARTS=1` 仅供历史兼容回归夹具，正式环境不配置。

## 复核修复与验证

复核修复了本地库存与云档案不一致、旧结算快照回滚资产、重复兑换与未知结果重试、禁止按钮仍会触发点击，以及首页加载提示覆盖结算标题的问题。范围内验证不能替代完整反作弊审计；生成合法操作的自动化玩家、救场授权及广告平台验签不属于商城扣款的事务保证。

`server/test/shop.test.js` 覆盖价格/数量篡改、双击/并发透支、幂等冲突、落盘故障、库存刷新、实际工具重放和补给次数；模块测试覆盖乱序及无版本回执。`scripts/verify-shop.cjs` 使用独立临时数据库和真实 API，验证实际界面点击、响应丢失重试、两种道具使用和结算、不同屏幕截图，不修改玩家存档或访问外网。产物在 `output/shop-verification/`。
