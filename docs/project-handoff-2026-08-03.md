# 《烦恼排排消》项目交接与代码审查（2026-08-03）

> 这是当前项目最可信的状态文档。下一次对话先读取本文件、根目录 `README.md` 与 `docs/formal-ui-implementation-v2.md`。  
> **已定稿产品方向（方案 B）：** 表情进度跨日永久累积；每满 666 得到 1 枚开心瓶；开心瓶贯通收集与解忧秘境等成长内容。  
> 已废弃、不可恢复：每日重置瓶、顺心周瓶日历、单瓶领道具、整周庆祝、「开心果 / 18 颗许愿瓶」等方案 A 内容。

## 1. 产品北极星

### 1.1 定位

- 平台：微信小游戏，竖屏，IAA 变现。
- 人群：全年龄，不把画面做成明显女性向，也不做幼儿园式低幼包装。
- 使用场景：3～12 分钟碎片时间，提供轻挑战、秩序感和即时反馈。
- 核心玩法：只做“左右移动横向色块，填满整行后消除”；成长、收集和分享只能服务留存，不能改变局内战力。
- 心理负担：不做断签惩罚、不制造养成焦虑、不以心理治疗或真实运势为宣传承诺。
- 商业原则：通过明确的救场、道具和复活价值引导广告，不暗改随机结果逼看广告。

### 1.2 包装主线

```text
杂乱的多色情绪
  → 左右整理位置
  → 满行消除并碎裂
  → 表情沿曲线飞入开心瓶
  → 瓶内水位上升、瓶盖打嗝
  → 满瓶计入开心瓶，并留下经验成长
```

当前名称为《烦恼排排消》，场所概念为“心情整理所”。唯一需要长期强化的视觉记忆点，是“色块碎裂—表情飞瓶—水位增长—瓶盖弹起”这一条完整因果反馈。

## 2. 当前可运行成果

### 2.1 首页

- 暖色日漫软 3D 工作室背景，与局内房间背景分开。
- 低对比彩色心情块水印墙；积极表情占主要比例。
- 左上档案卡：默认头像、名称、等级、经验进度；包含微信头像昵称授权入口和本地缓存。
- 档案卡旁展示开心瓶数量；演示区展示当前正在收集的一瓶水位（目标 666）。
- 正式艺术字标题《烦恼排排消》。
- 局外慢速玩法演示：拖动、下落、消除、表情飞瓶和瓶盖反馈。
- 次级入口：解忧秘境、排行榜；设置入口可调音量/震动，含 GM 发放。
- 绿色“开始消除”按钮；正式手指素材从右下斜向伸入，点击时出现三层水波纹弱引导。
- 玩法提示每隔数秒淡入淡出。

### 2.2 核心玩法

- 棋盘：8 列 × 10 行，逻辑格 76 设计像素。
- 色块：长度 1～3 格，只允许左右移动，随后受重力下落。
- 满行消除：基础分为 `满行数 × 10 × 连消层级`。
- 下一排：位于棋盘下方遮挡板内，新行由底边进入，不在棋盘外显示完整色块。
- 棋盘层级：盘面、参考网格、裁剪交互层、生成帘、顶层边框。
- 消除后立即进入重力流程，没有额外 500ms 空档。
- 约 50% 色块带线稿表情，固定在横块左侧；右侧保留未来收藏物位置。
- 10 种心情：6 种积极、4 种轻度消极；初始生成权重约 3:2，消除增多后逐渐偏向积极和平静色。
- 消除光效已减弱，碎裂粒子已增加。
- 8 秒无操作且存在可消除机会时，小手演示一次有效移动；任何触摸立即打断并复位。
- 前 10 次挑战主要显示玩法提示，之后降低频率并切换暖心文案。

### 2.3 顶部信息与收集

- 本局分数与历史最高分同卡对比。
- 未破纪录时“最高记录”位于右侧；破纪录后缓动移到本局分数下方并变色。
- 分数和收集数量更新时有轻量呼吸动画。
- 开心瓶采用从下到上的液面进度，不使用横向进度条或玻璃珠。
- 带表情色块消除时，表情沿二阶贝塞尔曲线飞入顶部瓶子；到达后刷新数字并触发瓶盖打嗝。

### 2.4 广告道具、救场和复活

- 解压锤：看视频获得 1 次机会；领取后立即进入待使用态，可点击选择目标，也可从入口拖放到目标色块。库存跨局保留。
- 魔法棒：看视频获得 1 次机会；领取后立即选择一种颜色，清除场上全部同色块。库存跨局保留。
- 两种道具待使用时，屏幕中央显示闪烁提示，棋盘全部色块轻微抖动；选择完成后统一退出该状态。
- 危险救场：棋盘距顶部约两行时，每个复活阶段最多弹出一次；看完视频自动清除“块数最多、并列时占格更多”的颜色。
- 复活：每次挑战一次；看完视频后播放闪电和碎裂效果，清除棋盘上半区，保留下半区继续。
- 复活后危险救场可再触发一次；复活后再次失败直接结算。
- Web 预览使用模拟视频弹窗；微信路径已调用 `createRewardedVideoAd`，但尚未配置正式广告位或完成真机验收。

### 2.5 结算与成长

- 结算中央显示本局得分，下方分别显示表情数量和经验数量；满瓶时额外提示开心瓶入账。
- 每收集 1 个表情固定获得 1 点经验，连消不额外增加经验。
- 每级经验目标：`ceil(15 × 1.32^(等级-1))`。
- 返回主页或重新再来时，经验图标飞向经验条，表情图标飞向主页开心瓶。
- 表情进度跨日永久累积；每满 666 得到 1 枚开心瓶，余数继续累计。
- 重复调用单局结算不会重复写入奖励。

### 2.6 云服务、排行榜与解忧秘境（v1.1）

- `CloudService` 接入匿名档案、云结算与双周榜（实力 / 开心瓶）。
- 服务端：Express + sql.js，部署路径见 `server/`。
- 解忧秘境：主题画册书架；每 5 级解锁一册，册内画作用开心瓶顺序点亮；当前客户端本地持久化，服务端权威尚未统一。

## 4. 代码结构

```text
assets/script/
├── GameMainScene.ts              # 首页、云、秘境、排行榜、结算返场
├── dataModule/ZyxGameModule.ts   # 棋盘唯一数据源、数值、存档、结算
├── manager/
│   ├── Uimanager.ts              # UI 工厂、三色按钮、Toast、通用弹窗
│   ├── CloudService.ts           # 云档案 / 结算 / 周榜
│   ├── GameSettings.ts           # 音效音量 / 震动偏好
│   └── SettingsPanel.ts          # 设置面板与 GM 发放
└── zyxGame/
    ├── MoodArt.ts                # 色谱、表情、色块材质、瓶子、两套背景
    ├── ZyxGame.ts                # 局内流程、HUD、动画、道具、广告、救场、复活、结算
    └── ZyxGridCom.ts             # 单个色块的点击与左右拖动手势
```

核心数据与 UI 已经分离：棋盘占用、移动范围、重力、消除、计分和结算都在 `ZyxGameModule`，表现层不应自行修改棋盘数组。

## 5. 本轮代码审查结论

### 5.1 本轮已经修复/加固

- 正式位图不再被 `Sprite.SizeMode.CUSTOM` 强制拉伸。UI 工厂统一按 Cocos 自动裁边后的 `SpriteFrame.getRect()` 做 contain 缩放；解压锤、魔法棒和首页指引手共用该逻辑。
- 激励视频增加一次性完成保护。`onClose`、`onError`、`show/load` Promise 异常即使竞态到达，也只能结束一次请求，不会重复发放奖励或重复恢复状态。
- 激励视频创建、方法缺失和同步异常均能回落到失败结果，不会让局内永久锁死。
- `stampCell` 不再被底层固定写成 0，并会限制在当前色块范围内，为后续收藏物/表情布局保留正确数据语义。
- 三张停用历史背景移出 `assets/resources` 到 `docs/art-sources/archive`，保留追溯但不再进入发布包。
- README 已更新，不再误写“每局 3 次锤子、没有广告流程”。
- Canvas 改为竖屏固定宽度策略，首页和局内根据实际屏幕高度重新排布；微信环境会把 `safeArea` 与右上角胶囊从物理像素换算到 Cocos 设计坐标，局内 HUD 在胶囊存在时切换为紧凑布局。
- 微信发布链已固化为 `npm run build:wechat`：构建后自动写入正式 AppID、竖屏方向与基础库 `3.15.2`，不再依赖旧工程残留配置。
- 三张仅作为小尺寸道具展示的正式纹理将最长边收敛到 640 px；微信发布包由 4480 KB 降到 3407750 字节，并通过开发者工具完整预览编译。
- **方案 B 收口：** 删除周瓶日历 UI 与相关数据 API；进度字段统一为 `happyBottleProgress` / `HAPPY_BOTTLE_TARGET`；不再写入 `zyx_wish_calendar`。

### 5.2 没有发现的高危问题

- 当前棋盘重力顺序、同行碰撞、满行判断、连消递归与顶部失败判断逻辑一致。
- 复活前后救场次数状态符合当前规则。
- 结算数据写入具有幂等保护，没有发现重复发放经验和开心瓶进度的直接路径。
- 所有局内资源动画均不直接修改最终奖励数值，动画中断不会二次入账。

这不等于已经达到上线可靠性：当前没有自动化单元测试、真机生命周期测试和弱网广告测试。

### 5.3 保留但不应在无测试时贸然拆分

- `ZyxGame.ts` 约 2600 行，承担局内流程、特效、广告弹窗与结算 UI，职责偏多。
- `GameMainScene.ts` 承担首页、云、秘境、授权和结算返场，职责也偏多。

下一次结构拆分前，应先为 `ZyxGameModule` 建立纯逻辑测试，再按边界拆成 `BoardView/Effects`、`RoundFlow`、`RewardedFlow` 和平台服务。不要为了行数好看而大拆文件，避免在缺少回归测试时引入时序问题。

## 6. 与设计初衷的符合度

### 已经对齐

- 核心操作始终是左右消，没有加入颜色匹配、战力或关卡养成干扰。
- 等级只记录游戏时长，不提供局内优势。
- 画面从偏粉/偏幼儿转向暖色日漫软 3D，男女老少都能接受。
- 消极表情控制为轻度、低占比，没有恐惧、厌恶或强烈哭泣。
- “整理混乱”的感受已通过左右挪动、满行消除、色盘逐渐积极化表达。
- 失败后有救场、复活和快速再来，挫败链路已打通。
- 广告都对应清晰价值，没有接入强制插屏。
- 开心瓶收集与解忧秘境成长已选定方案 B，不再维护每日签到式周瓶。

### 仍有明显差距

1. **满瓶节奏的实际负担未知。** 每个带表情色块只计 1 个，出现率 50%。没有真实局长和收集效率数据，无法证明普通玩家约多少局能攒满一瓶。
2. **难度仍只有少数旋钮。** 主要依赖新排占格从 4→5→6 和随机空隙；没有随机种子、可复盘配置、可解性保护或广告后缓冲配置。
3. **“越玩越清晰”只实现了一半。** 新生成色盘会逐渐积极和收敛，但场景、瓶子和棋盘没有更强的阶段性秩序变化。
4. **美术仍是垂直切片。** 背景接近方向稿质量，色块和大部分 UI 是程序美术；字体、图标、弹窗和软 3D 细节尚未达到整套商业游戏资产的一致度。
5. **收集运营尚未充分实现。** 数据结构预留了收藏物位置；秘境仅第一册可玩，服务端权威未统一。
6. **IAA 平衡尚未成立。** 解压锤和魔法棒用完后可继续看广告补充，尚无每局/每日软上限；需要用数据决定广告频次。
7. **云端可靠性。** 离线结算无 outbox；秘境解锁仍是本地权威；匿名设备令牌不足以抗伪造结算。

## 7. 上线前必须补齐的工程差距

### P0：下一阶段首先处理

1. 微信真机适配抽测：安全区、胶囊避让、固定宽度与长短屏动态布局已经实现，并在 375×667、360×720、390×844 三档竖屏模拟中通过；仍需至少一台刘海 iPhone 和一台低端 Android 真机确认触摸、字体及系统按钮边界。
2. 微信广告与生命周期：开发者工具构建、预览和版本上传已经完成；正式 `adUnitId`、真机 `onShow/onHide`、切后台、来电恢复和广告失败链仍未验收。
3. 广告服务抽象：当前入口已集中在一个函数，但实例、配置、生命周期和事件上报仍在 `ZyxGame`；正式接入前应独立为 `AdService`。
4. 核心逻辑测试：至少覆盖移动范围、重力、满行、连消、推进失败、救场颜色选择、复活清理、重复结算和持久化存档。
5. 数值埋点：记录回合数、消除数、表情数、危险高度、广告结果、复活后存活回合和结束原因。
6. 统一秘境解锁权威，并增加离线结算 outbox。

## 8. 已知体验选择与待确认项

- 暂停页“重新开始”当前会先静默结算本局已获得资源，再开始新挑战；逻辑公平，但没有结算返场动画。后续需决定是保留资源并快速重开，还是统一经过结算页。
- 广告失败不会扣道具，也不会结束游戏；复活广告失败会重新展示复活选择。
- 旧基础库广告关闭结果可能没有 `result`，当前按完整观看处理；发布前按目标最低基础库重新确认。
- 头像昵称已经实现原生授权按钮覆盖逻辑，但必须在微信开发者工具和真机确认位置、层级、拒绝授权与重新授权流程。
