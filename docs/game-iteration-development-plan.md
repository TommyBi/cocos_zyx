# 《烦恼排排消》可执行开发方案 v1.0

> **历史基线提示（2026-08-03）：** 本文第 2、3、6 节保留最初“开心果 / 18 颗”方案用于追溯，当前实现已经改为“直接收集色块表情 / 每日目标 666 / 每个表情同时提供 1 点经验”。最新完成度、代码审查与下一轮优先级请以 [`project-handoff-2026-08-03.md`](./project-handoff-2026-08-03.md) 为准。

> 产品定位：竖屏、全年龄、低压力、回合制左右消除微信小游戏。核心操作始终是“左右移动心情块，填满整行后消除”。局外成长和收集只服务留存，不提供局内数值优势。

## 1. 产品目标

### 1.1 核心体验承诺

玩家每次进入游戏，都经历一条清晰的情绪曲线：

```text
杂乱的多色情绪
  → 左右整理
  → 满行捋顺
  → 凝结开心果
  → 结算装入许愿瓶
  → 当日留下一个正向记录
```

### 1.2 目标用户

不按年龄定义唯一用户，而按使用动机定义：希望在3～12分钟碎片时间内获得秩序感、轻挑战和即时反馈的人。

### 1.3 商业模式

- IAA为主，不售卖局内战力。
- 普通玩家的主要广告场景：棋盘救援、道具补充。
- 高水平玩家的主要广告场景：经验翻倍、收藏加速、海报模板。
- 不通过暗改随机数强迫观看广告。

## 2. 当前临时版本状态

截至本方案建立时，项目已完成以下可运行闭环：

- 首页更名为《烦恼排排消》，场所命名为“心情整理所”。
- 暖阳窗边临时背景已接入。
- 五种临时心情：愤怒、犹疑、开心、平静、思念。
- 每个心情块带有独立的小型“心情印”。
- 消除行数累计为本局开心果。
- 开心果在消除时飞入顶部“本局收集”区域。
- 结算时开心果进入每日许愿瓶。
- 每日瓶目标暂定18颗，标签分为“明日顺利 / 明日大吉 / 大吉大利”。
- 许愿瓶装满后的溢出开心果转为经验。
- 首页展示等级、经验和最近七天顺心日历。
- 本地进度使用 `cc.sys.localStorage` 持久化。
- Web Mobile构建通过，并在375×667竖屏下完成首页、玩法、暂停、结算截图验收。

临时版尚未包含：微信登录、云存档、激励视频SDK、正式月历、正式分享海报、正式音频、服务端难度配置和正式美术资源。

## 3. 数据模型

### 3.1 单局数据

| 字段 | 含义 |
|---|---|
| `score` | 当前顺心值，仅用于单局挑战与排行榜 |
| `bestScore` | 历史最顺纪录 |
| `turn` | 当前有效操作回合数 |
| `roundClearedRows` | 本局已消除行数，同时是本局开心果数 |
| `hammerCount` | 本局松松锤数量 |
| `pieces` | 棋盘心情块状态 |
| `nextPieces` | 下一行预告 |

### 3.2 每日数据

| 字段 | 默认值 | 说明 |
|---|---:|---|
| `dailyWishTarget` | 18 | 每日许愿瓶目标，必须可配置 |
| `dailyWishFruit` | 0 | 当日已装瓶数量 |
| `wishTier` | 0 | 0空瓶、1顺利、2大吉、3大吉大利 |
| `dailyMoodChoice` | 暂无 | 后续可增加“开心 / 平静 / 勇气”等每日选择 |

### 3.3 长期数据

| 字段 | 说明 |
|---|---|
| `level` | 顺心等级，不影响局内能力 |
| `experience` | 满瓶后的开心果溢出经验 |
| `calendar` | 日期到许愿瓶档位的映射 |
| `moodAlbum` | 心情图鉴与出现次数，第二阶段实现 |
| `cosmetics` | 瓶子、标签、房间摆件、海报边框 |

### 3.4 存档原则

- 所有存档带 `schemaVersion`，升级时执行显式迁移。
- 本地存档先保证离线可玩；微信云存档作为覆盖层，不阻塞首局。
- 每次结算后写入，避免每帧或每次拖动写存储。
- 服务端只保存用户进度和配置版本，不保存可由棋盘重建的动画状态。

## 4. 难度系统方案

### 4.1 当前问题

当前难度主要由新行填充格数从4提升到5、6控制，维度太少。随机结果可能同时影响压力和可解性，无法细致平衡。

### 4.2 拆分的难度旋钮

1. 新行占用格数。
2. 长块与短块的比例。
3. 新行空隙的破碎程度。
4. 连续无直接消除机会的回合数。
5. 下一行预告信息量。
6. 危险状态下生成“可救布局”的概率。
7. 道具初始数量与广告补充次数。

### 4.3 推荐单局阶段

| 阶段 | 参考回合 | 目标体验 |
|---|---:|---|
| 舒展期 | 1～8 | 快速学会移动与满行反馈 |
| 顺手期 | 9～18 | 开始观察下一行 |
| 忙碌期 | 19～30 | 需要两步规划，连消增多 |
| 告急期 | 31～45 | 多次接近顶部，但保留自救机会 |
| 极限期 | 46+ | 服务高手排行榜，经济奖励逐步封顶 |

### 4.4 公平性约束

- 同一随机种子必须能复现整局。
- 难度按阶段与配置变化，不根据玩家即将成功而临时改坏下一行。
- 棋盘达到危险高度且连续多回合无消除时，可触发一次“缓冲生成”，但必须记录事件。
- 广告救援后至少提供一段有实际操作空间的缓冲，不能两三回合后再次必死。
- 高手的收益上限通过每日资源封顶解决，不通过降低成功概率解决。

## 5. 心情色谱与视觉进程

### 5.1 第一批心情

首发只使用5～6个玩法色系，每局保持可读性。完整图鉴可以扩展到24或36种。

| 编号 | 心情 | 色系 | 整理后的相邻状态 |
|---:|---|---|---|
| 1 | 愤怒 | 珊瑚红 | 勇气 |
| 2 | 犹疑 | 杏橙 | 好奇 / 确定 |
| 3 | 开心 | 柠檬黄绿 | 满足 |
| 4 | 平静 | 鼠尾草绿 | 安心 |
| 5 | 思念 | 雾霾蓝 | 宁静 |

### 5.2 单局色盘变化

- 消除0～2行：五个色系混合。
- 消除3～6行：新行减少强烈冲突色，平静色权重提高。
- 消除7～11行：新行以三个协调色系为主。
- 消除12行以上：以开心、平静和邻近色为主。
- 已存在色块不强制变色，通过自然消除和新行生成完成过渡。
- 色彩变化当前只影响表现，不加入颜色匹配规则。

## 6. 许愿瓶、等级与月历

### 6.1 每日许愿瓶

初始临时规则：

- 每消除一行获得1颗开心果。
- 本局开心果在结算时统一装瓶。
- 1～49%：“明日顺利”。
- 50～99%：“明日大吉”。
- 100%：“大吉大利”。
- 空白日期保持中性，不使用失败、断签或红色警告。

`18` 只是临时目标。正式目标必须根据“普通用户装满所需分钟数”调节，首轮目标为普通用户8～12分钟、2～4局完成。

### 6.2 满瓶后的经验

- 满瓶后每颗开心果转1点经验。
- 等级不提升局内能力。
- 每5级可解锁标签皮肤、瓶子装饰或海报边框。
- 内容未制作完成时允许等级继续增长，不承诺每级奖励。

### 6.3 顺心日历

- 未游玩：奶油白。
- 明日顺利：浅米黄。
- 明日大吉：杏橙。
- 大吉大利：蜂蜜金。
- 月历只记录，不制造考勤压力。
- 月末输出“本月好运报告”，展示开心果总数、大吉日数、最佳单局和轻量称号。

## 7. IAA实施方案

### 7.1 广告位

| 场景 | 用户 | 奖励 | 限制 |
|---|---|---|---|
| 棋盘告急 | 普通玩家 | 腾出部分空间或清理若干行 | 每局1次起步 |
| 松松锤耗尽 | 普通玩家 | 补充1次道具 | 每局1次 |
| 结算经验翻倍 | 高手 / 满瓶玩家 | 本局溢出经验翻倍 | 每日上限 |
| 月报高级模板 | 收藏玩家 | 解锁一次高级分享样式 | 不影响数值 |

### 7.2 技术要求

- 抽象 `AdService`，游戏逻辑只接收“成功完整观看 / 未完成 / 加载失败”。
- 激励视频实例在微信小游戏端集中管理，避免每个弹窗各自创建。
- 只有完整观看后发放奖励；关闭、错误、无填充均回到可继续操作状态。
- 广告失败不能扣除已有道具或结束当前游戏。
- 首次若干局不主动弹出插屏或强提醒。

微信官方当前提供 `wx.createRewardedVideoAd` 创建激励视频组件，实际接入前仍需按发布时基础库与广告合规要求复核：

- https://developers.weixin.qq.com/minigame/dev/api/ad/wx.createRewardedVideoAd.html

## 8. 微信小游戏适配

### 8.1 平台适配层

新增统一接口：

- `StorageService`：本地与云存档。
- `LifecycleService`：前后台切换、音频暂停恢复。
- `AdService`：激励视频与插屏。
- `ShareService`：好友转发、月报海报、启动参数。
- `AnalyticsService`：行为事件与配置版本。

核心棋盘模块不得直接调用 `wx.*`，保证Web预览和微信环境都可运行。

### 8.2 分包建议

- 主包：启动、首页、核心玩法、通用UI、首批心情资源。
- 普通分包：完整月历、图鉴、排行榜、设置。
- 季节资源分包：活动场景、瓶子皮肤、海报模板。
- 独立分包候选：只展示分享月报或排行榜的轻入口。

微信官方独立分包可在分享入口中独立启动，适合后续“好友打开月报/排行榜”的快速访问场景：

- https://developers.weixin.qq.com/minigame/dev/guide/base-ability/independent-sub-packages.html

### 8.3 分享

- 单局分享：强调差一格、连续消除或新纪录。
- 月报分享：强调本月颜色、开心果和称号。
- 好友打开后进入轻落地页，再由用户主动开始游戏。
- 分享参数记录海报版本和入口，不携带敏感用户数据。

微信官方 `wx.shareAppMessage` 支持标题、分享图和查询参数；分享图当前文档说明为5:4，制作前以发布时官方文档为准：

- https://developers.weixin.qq.com/minigame/dev/api/share/wx.shareAppMessage.html

## 9. 埋点与调参

### 9.1 必须事件

| 事件 | 关键参数 |
|---|---|
| `round_start` | 难度配置版本、历史最佳分、每日瓶进度 |
| `piece_move` | 回合、移动距离、棋盘最高占用行 |
| `row_clear` | 行数、连消层级、本局累计开心果 |
| `danger_enter` | 棋盘高度、连续未消除回合 |
| `ad_offer` | 广告位、当前棋盘状态 |
| `ad_result` | 完成 / 关闭 / 失败、奖励类型 |
| `round_end` | 分数、回合、消除行数、结束原因 |
| `wish_upgrade` | 旧档位、新档位、所需局数和分钟数 |
| `level_up` | 等级、经验来源 |
| `share_generate` | 海报模板、月历完成度 |
| `share_open` | 来源参数、冷启动 / 热启动 |

### 9.2 首轮关注指标

- 首局有效拖动完成率。
- 首局消除至少一行的比例。
- 平均单局回合、平均消除行数、结束原因分布。
- 许愿瓶首档、半瓶、满瓶所需局数与分钟数。
- 结算后“再顺一局”点击率。
- 救援广告展示、完成与救援后存活回合。
- 月报生成率和分享打开率。

不要先设拍脑袋的商业目标；先拿到一周自然流量或内部测试分布，再确定难度与广告实验。

## 10. 分阶段排期与验收

### P0：包装垂直切片（当前已完成临时版）

- 首页、玩法、结算统一暖阳视觉。
- 心情块、心情印、开心果、许愿瓶闭环。
- 每日进度、等级、本地月历记录。
- Web构建和竖屏视觉验收。

### P1：正式美术替换与手感打磨

- 接入正式首页、玩法背景、棋盘、按钮、瓶子和心情印。
- 补音效、触感与完整压平—化光—飞果动画。
- 增加设置页和正式月历页。
- 验收：低端机稳定、文字无裁切、核心操作区无遮挡、色弱模式可辨认。

### P2：难度配置与数据闭环

- 随机种子与对局复现。
- 拆分难度旋钮、远程配置和事件上报。
- 内部模拟与真人测试。
- 验收：相同种子可复盘，参数无需发版即可灰度调整。

### P3：微信平台与IAA

- 微信构建、启动生命周期、存储适配。
- 激励视频管理器、救援和经验翻倍。
- 广告失败降级流程。
- 验收：弱网、无广告填充、切后台、来电中断均不丢局。

### P4：月报分享与轻收集

- 完整月历、月报海报生成、好友打开落地页。
- 首批瓶子标签、房间摆件和心情图鉴。
- 验收：海报信息可读、分享入口可追踪、收藏不提供战力。

### P5：小流量投放与迭代

- 分素材测试“差一格”“心情整理”“许愿瓶月报”三种创意。
- 按用户水平拆分广告需求，不按用户水平暗改难度。
- 以留存、再开率、有效广告次数和负反馈共同决策。

## 11. 上线前检查清单

- 核心玩法在无网络、无登录、无广告情况下可完整游玩。
- 当日切换、跨月、系统时间变化不会损坏日历。
- 暂停重开也会正确结算已获得开心果。
- 重复结算不会重复发放奖励。
- 满瓶溢出经验、升级和存档均可复现。
- 背景与特效不影响棋盘边界识别。
- 心情印在小屏、低亮度和色弱模式下可辨认。
- 分享内容不声称心理诊断、治疗或真实运势预测。
- 广告奖励发放条件、失败恢复和次数上限可配置。
- 正式构建关闭调试性能信息并完成真机性能测试。
