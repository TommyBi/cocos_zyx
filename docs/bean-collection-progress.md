# 开心豆局内收集与 HUD

## 当前产品规则

- 每局从 0% 开始。每消除一个带表情的心情块，累计 1%；百分比使用整数显示。
- 每累计 100 个带表情块，自动获得 1 颗开心豆。允许一局获得多颗；同次消除跨越满格后，余量继续留在本局下一轮。
- 本局结束后，未满一颗的余量不跨局。经验仍按每个带表情块 1 点独立累计。
- 「本局 +N」只表示本局形成的整颗开心豆，不是钱包总余额。可用余额只在服务端确认结算后更新。
- 结算预览、结算弹窗和服务端奖励使用同一换算。历史变量 `roundCollectedMoodBeans`、请求字段 `collectedMoodBeanCount` 继续表示原始表情块数量，以兼容重放与历史队列，不能直接作为整颗豆子数展示。
- 首页排行榜下方已加入商城：解压锤、魔法棒各20豆兑换1个，体力5豆兑换1点；钱包和库存由服务端确认，详见 `docs/shop.md`。

## HUD 与适配

- B 方案：左侧较弱的得分卡；右侧收集卡，绿色「收集进度」标题胶囊、醒目的百分比、圆环和豆子头像；半透明暖棕徽标常驻显示「本局 +N」。两卡、下一排、道具栏共用纯净奶油色、暖棕描边、24px 圆角，不再使用各自拉伸的整图背板。
- 卡片逻辑高度 148。顶部随排行收展在 642～738 宽之间同步过渡；收起时与棋盘居中，展开时与“排行＋棋盘”的整体轮廓居中，左右各多出 8px。内容与背板预留独立内边距，圆角和描边不随宽高拉伸。
- 专用 BMFont `hud_round_v1.fnt` + `hud_glyphs_v1.png` 固定字重和字形；数字使用圆润粗体，中文为加粗栅格字。仅分发栅格字形，不复制系统字体源文件。重建脚本为 `scripts/build-hud-font.py`。
- 百分比字号 64，本局数量 24，当前得分 46；辅助说明 22。固定区域、不换行，位数增多时字号收敛并由 SHRINK 保证边界；百万以上分数用「万」、亿以上用「亿」，避免极大分数和最高分变成难读的小字。
- 圆环与百分比平滑推进；满格停留 0.32 秒并显示「开心豆 +1」，数量轻弹，再显示余量。连续到达合并处理，跨多颗逐段播放，结束或离场可安全中断。
- 舞台最小高度 1444；同步调整 HUD 与棋盘区域间距。Web Debug 的默认 GM 气泡移至顶部空隙，避免遮住得分；玩家自己拖动保存的位置继续保留。

- 统一背板：`assets/script/zyxGame/GamePanel.ts`，共用抗锯齿九宫格纹理，纯净实色、不带布纹或发白渐变。
- 上一版两张面板素材已移出运行时 Bundle，保留在 `docs/art-sources/bean-hud-v1/superseded-panels/`。
- 完整提示词：`docs/art-sources/bean-hud-v1/prompts.json`。

## 协议与发布边界

- 新客户端检查 `bean-collection-progress`、`adaptive-combo-v2` 和 `bean-collection-1pct`，再使用 `collectionRule=progress_v2`、`rulesVersion=2` 开局；不支持新规则的服务端不会被调用开局扣体力。
- 服务端按开局记录锁定折算：`progress_v2` 每 100 表情一豆，`progress_v1` 保留每 10000 表情一豆，legacy 保留旧协议；客户端不能通过结算参数提升倍率。新旧进度协议的正数收集都需要重放，棋盘 V2 对局还必须有完整版本标记。
- 当前schema v8支持库存、资产版本与道具事务，默认只允许 `progress_v2` + 棋盘V5新开局，重试不能切换协议。2026-11-12发布另行执行一次性进度/资产重置，保留资料与排行榜，详情见CR报告。
- 进度协议支持长局最多 100000 条操作，JSON 上限 2 MB，原始表情块数上限 1000000（新进度规则最多 10000 颗，旧进度规则最多 100 颗）。不再用旧 5000 数量上限静默截断新规则长局。
- Web Debug 本机显式使用 `?localApi=1` 才连接 `127.0.0.1:8080`；正式网页和微信忽略本机调试参数。
- 本地预览使用 `server/data/game.sqlite`；两线上环境已升级，当前发布与备份证据见 `docs/code-review-2026-11-12.md`。

## 验收

- 单元/集成测试覆盖换算边界、每局清零、独立经验、旧协议、重放、跨多颗、动画合并/中断、大数字和安全区。
- 新增长局 API 测试使用接近 100000 条真实重放操作，覆盖超过两万表情块、多颗奖励、旧资产保留、重复提交和可靠落盘。
- 用户明确授权后，以独立的无头 Chrome 运行 `scripts/verify-bean-hud.cjs`，不操作用户现有浏览器。
- `scripts/verify-bean-identity.cjs` 另从首页冷启动、完整排行榜和实际结算检查开心豆资源；`identity-results.json` 保存各位置的同一资源 UUID。
- 实际截图尺寸：390×844、320×568、768×1024、540×900、1024×768；检查实际加载位图字、文字边界、100% 停留、多颗计数和余量；大数字截图覆盖九位分数的万/亿格式和五位本局数量。先执行真实教学消除，验证 10 分、3% / 本局 +0，再拍摄展示样例。
- 最新截图与结果位于 `output/unified-ui-verification/`，包含排行展开/收起状态、共用背板与豆子资源 UUID 的实际检查。上一版截图保留在 `output/bean-hud-verification/`。参考状态中的 2400 分、3 颗、37% 和测试对手是该独立浏览器中的展示样例，没有修改经济数据。截图中隐藏 Web 专用 GM 气泡，以正式产品界面核对美术。
- 微信真机视觉、原生分享与发布环境验收尚未执行。

## 1% 规则补充验收

首步真实消除三个表情后显示 3%；99→101 的展示验证先停留 100% 并增加一颗，再显示 1% 余量；继续到 201 显示两颗与 1%。满格“开心豆 +1”提示临时替换卡片底部说明，不遮挡标题或百分比。服务端测试以真实棋盘操作验证新局每百表情一豆，旧局保持原倍率，重复请求不再次入账。当前截图见 `output/fire-cloud-onepct/`。
