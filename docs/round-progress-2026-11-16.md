# 未结算对局保存与续玩

> 2026-11-17补充：当前本地候选为V11/API15/结构10，复活卡扣库存与完整复活存档同事务提交，恢复和最终结算核对用卡凭据；V10保存局仍可恢复并保持原一次复活。详见 [复活卡交付](revive-card-2026-11-17.md)。下文API14/结构9为首版保存功能记录。

设计与实施：2026-11-16。范围为新协议开局，旧对局/旧客户端结算继续兼容，不改既有玩家资产。

- 一个账号保留一个可续玩的新协议对局。每次完整操作在安全边界落本地，每100次完整操作同步；暂停/切后台/恢复网络补存。进度本身不入账、不进榜，最终结算沿用原局ID幂等发奖。
- 后端保存并重放种子+规范化操作序列，分数、收集数、步数全部重算；已确认的操作前缀不可更改/截短结算。保存请求可幂等重试，迟到旧请求不能回滚进度。
- 启动先补传结算，再检查未结算局。温馨提示默认“稍后再玩 / 继续上局”，继续不扣体力。主界面开始入口可选择放弃旧局并新开，明确说明消耗体力；后端在新开成功事务中放弃旧局，失败保留旧局。
- 恢复使用服务端核验后的操作重建棋盘、随机状态、连消、下一排、救场状态和已用复活。不能直接信任本地棋盘/分数/余额。优先核验同账号、同环境本地尾部操作；尾部核验失败须由用户明确选择退回云端存档，不能静默丢进度。
- 每次恢复通过版本条件和幂等请求ID更新对局会话凭证；旧会话不能继续保存、消费道具或结算。多端冲突重新查询，不覆盖新进度。
- 保持7天离线补传窗口和4小时有效局内时长约束；离线停留不计入恢复后的局内时钟。临时救场提示/广告不重放为已完成奖励，恢复时按提示过期处理，保留已使用记录与冷却。
- 突然杀进程时后台请求不能保证完成；同设备优先找回本地已完成操作，清缓存/换设备只能恢复到后端最后确认点。微信账号绑定用于跨设备识别；匿名账号不能承诺清缓存恢复。
- 新能力通过API14/结构9及 `round-checkpoints-v1` 协商；未升级后端时禁止新客户端扣体力开局。本轮先完成本地实现与验收，部署/微信上传单独交付。

## 接口和实现

- `POST /games/start` 新客户端传 `resumeProtocol: 1`，取得本局 `sessionToken`；同一开局ID重试不重复扣体力。已有保存局时拒绝另开；明确重开需指定旧局ID及代次，在新开成功事务中把旧局标为abandoned。
- `GET /games/active` 返回本人有效保存局摘要，不返回会话凭证和好友数据。
- `POST /games/checkpoint` 提交本局会话凭证、完整操作日志、有效时长。后端规范化日志并重放，检查道具扣减凭据、救场时间/次数和稳定边界；已存日志前缀不允许改写，迟到短请求只返回新确认点。
- `POST /games/resume` 携带期望代次和持久化的幂等请求ID，可附同代次本机尾部日志；核验成功后才换会话凭证并返回完整日志。并发恢复仅一个代次胜出。丢响应使用原ID及相同内容确认。旧会话的保存、道具与结算都拒绝。
- 结算队列保存会话凭证；结算必须覆盖已确认前缀，并继续原有种子重放、道具验证、资产版本及原子落盘幂等流程。保存和恢复本身不加豆子/经验/最高分。
- `RoundProgress.ts` 负责按账号/环境隔离的本地记录、每100次新操作的串行合并保存、失败退避、存储不足提示及恢复请求幂等。
- `RoundReplay.ts` 从核验日志重建纯棋盘，恢复随机状态、内部ID、combo、下一排和冷却；不导入不可信棋盘快照，不覆盖服务端库存。恢复教学步骤及已用复活，临时救场提示按过期处理。失败棋盘也保留，不能靠重进重获复活。
- 暂停页新增“保存返回”；原“退出”明确为“结算退出”。继续不扣体力；暂停和后台停留不挤占恢复后的有效局内时长。新续玩提示为二维纸卡，主操作在右侧。

## 验收与交付边界

203客户端测试、58服务端测试、类型检查和共享引擎一致性检查通过。Web/微信完整构建通过，微信主包2,862,115字节（2.73MiB），低于2.75MiB预算，GM隔离通过。专项覆盖100步阈值/串行合并、断网重试、本机尾部核验、重复和并发恢复、跨账号隔离、旧会话拒绝、存档前缀不能改写或截短结算、道具凭据、时间上限/7天到期，以及写盘故障后原请求重试。

真实隔离本地API在320×568、390×844、768×1024验证：冷启动弹窗、保留本机未上传操作、棋盘/下一排/随机状态完全一致、保存返回不结算、重进再次提示、不额外扣体力；390尺寸继续完成教学后按原局ID结算成功。页面异常0。证据 `output/round-progress-20261116/`，复验脚本 `scripts/verify-round-progress.cjs`（强制只允许本地服务）。

微信主包新增能力接近原预算，生成包大PNG额外做Zopfli DEFLATE无损重编码；逐像素、解压流和PNG元信息比对通过，额外减少22,895字节。构建依赖使用 `python3 -m pip install -r scripts/requirements-wechat-images.txt` 安装，不修改源图。

本轮不部署、不上传微信、不提交审核，不更新正式发布入口。正式发布前需先部署API14/结构9后端，再发布客户端，并完成手机后台/杀进程、断网和双设备实测。旧版已经丢失且未上传过操作的对局无法事后补救。清缓存/换设备仅恢复最后云端确认点；匿名Web账号清缓存不能承诺找回，微信跨设备依赖同一微信身份登录。重放检查可阻止伪造分数/道具和重复领奖，但不等于能识别所有生成合法操作的自动化外挂，原广告/分享奖励证明边界不因本功能提升。
