# 体力与服务端开局规则

> 2026-10-29 确认范围：打磨核心消除玩法；未来的实物权益货币按活动单独设计，本轮不创建权益货币账户或发放规则。

## 当前规则

- 自然体力上限10点，额外领取和兑换可超过自然上限。每开一局消耗1点，包括“再来一次”和暂停重开。
- 未满时每5分钟自然恢复1点，累计不超过10点。使用服务端时间，客户端倒计时只是展示。
- 首页以暖金色完整笑脸闪电显示当前体力。服务端确认扣点后闪电飞向开始按钮，再进入对局；开始按钮上方显示体力与恢复倒计时。
- 体力耗尽可分享领取5点，每个玩家按北京时间每天最多一次，可超过自然恢复上限；分享期间自然恢复的体力保留。`POST /stamina/share-claim`可靠落盘，重复ID不加点，跨日重试只确认历史结果、不占新一天次数。商城另支持5豆兑换1体力。
- 新局必须在线取得 `POST /games/start` 返回的开局 ID。请求携带客户端预先保存的 `roundId`，超时重试沿用同一 ID，服务端不会重复扣体力。体力不足返回 `STAMINA_EMPTY` 和最新体力状态。
- 已取得开局 ID 的对局允许中途掉线。结算先进入本地待提交队列，恢复联网后按同一 ID 补传。服务端只接受已领取开局 ID 且未结算过的对局，并按原有时间、分数和收集数量规则校验。
- 局内仍收集开心豆与经验；结算页显示本局收集量，首页资产余额只显示服务端确认值。开心豆不设置每日上限，余额以当前服务端档案为准。

## 数据与迁移

服务端为每个玩家保存体力及恢复基准时间，并为开局和结算保存同一 `roundId`。扣体力、登记开局、结算和发放开心豆都必须可靠落盘后才返回成功。重复开局和重复结算返回已保存结果。

微信分享接口不提供可供服务端独立验证的普通转发成功凭证；当前使用回到前台的完成信号并由服务端限制每天一次。该信号可被伪造，实物权益上线前必须改成可核验的激励视频回调或其他可信凭证，并绑定可信微信身份。

无服务端开局ID的历史对局不能补发资产。结构迁移本身保留数据；2026-11-12发布另行执行一次性进度与资产重置，保留账号资料和排行榜最高分，之后正常重启不再次清空。旧秘境投入不返还。

## 后续活动边界

实物权益规则待活动方案确定，不能直接将当前开心豆视为实物兑换余额。微信端已使用服务端换回的OpenID，Web预览仍是设备档案；服务端按绑定种子重放分数与表情数量，但分享/广告完成信号仍非平台验签，不等于完整反自动化和实物权益校验。

发布顺序为先更新服务端、确认 `/games/start` 可用，再发布需要开局许可的微信客户端。
