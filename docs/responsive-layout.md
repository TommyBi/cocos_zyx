# 多设备显示适配

## 布局规则

- 设计基准为 750 × 1334。窗口比基准更宽时固定逻辑高度，更窄时固定逻辑宽度，保证标题、档案卡、棋盘和底部操作区拥有完整空间。
- 首页主内容居中，最多使用 900 逻辑宽；排行榜和设置入口靠近主内容右侧。局内使用 750 逻辑宽、1390～1560 逻辑高的操作舞台。先将可用区域与刘海、微信胶囊底边、底部安全区相交，再整体缩放；局内不重复扣安全区。
- 首页和局内背景铺到整个画布。竖屏背景等比铺满并裁边；横屏保留竖版插画的高度，左右用同色背景和表情水印补齐，避免把插画拉宽。
- 首页微信安全区用于顶部档案、底部按钮和边缘入口。局内安全区只由外层舞台处理一次。首页头像目前只展示资料，不创建微信原生授权按钮。
- 如果浏览器提供视口分区信息，主舞台放在面积最大的单个分区内，避免跨过铰链；支持现行 `window.viewport.segments`、`visualViewport.segments` 及旧版 `getWindowSegments()`。无分区信息时采用普通单视口布局。分区能力并非所有浏览器都有，真机仍需验收。[W3C 视口分区规范](https://drafts.csswg.org/css-viewport/#dom-viewport-segments)
- 窗口尺寸变化时重新选择画布策略；首页重排，局内更新舞台位置、背景和 HUD/棋盘/下一排/工具/底栏的位置，保留棋盘、教学步骤、分数及当前弹窗状态。

## 已验证尺寸

| 窗口（CSS 像素） | 场景 | 结果 |
|---|---|---|
| 390 × 844 | 窄屏手机 | 标题、档案、开始按钮、体力和设置入口可见 |
| 820 × 1180 | 平板竖屏 | 首页与局内棋盘完整，入口无重叠 |
| 1294 × 1809 | 用户截图比例 | 标题与档案卡分离，首页内容完整 |
| 720 × 720 | 接近正方形窗口 | 内容居中，底部操作不裁切 |
| 1280 × 720 | 平板横屏 | 棋盘居中完整；局内从竖屏切换到横屏再切回，未重置对局 |

以上是本机浏览器视口验收；实际折叠屏铰链与安全区仍需对应真机检查。


## 2026-10-30 局内遮挡修复

旧实现只把 HUD 与提示条按全局安全边距移动，棋盘和工具停留在固定坐标，造成用户截图中的上下遮挡。现在 `insetGameRegion` 统一选取可用区，`calculateGameLayout` 按区域边界排列 HUD、棋盘、下一排、工具、底栏，包含投影和外框高度，区域间至少留 16 逻辑单位。长屏额外空间分配到各段间距。缩放舞台的拖动使用父节点局部坐标；收集飞豆目标也转换到飞行层坐标。

本轮用浏览器模拟 44px 顶部安全区、80px 胶囊底边、34px 底部安全区与示意系统遮挡，实际检查 414×896 教学局、375×667 小屏、1024×768 平板横屏，并在同一局内往返切换。分数栏、棋盘、下一排、工具与底栏无重叠；小屏拖动真实色块后进入教学第 2 步，10 分/3 豆在横竖屏切换后保留。模拟注入仅用于生成的本地预览 HTML，不进入源码与微信包。尚未做微信真机验收。


## 全屏弹窗遮罩

弹窗内容沿用安全区舞台，背景遮罩与触摸拦截则覆盖完整画布，包含顶部/底部安全边距、横屏左右补景与分屏舞台外区域。`UIManager.refreshModalLayout` 将完整 Canvas 的两个边界角转换到弹窗局部坐标；窗口重排后同步更新遮罩，不移动弹窗内容。遮罩不参与面板的入场缩放。启动 Canvas 宿主与局内舞台宿主均有回归检查。

浏览器以 44px 顶部、80px 胶囊底边、34px 底部安全区模拟，实际打开暂停设置，检查 414×896 到 1024×768 的窗口切换，背景遮罩无缺口，顶部空白点击不关闭暂停弹窗，面板按钮可操作；没有 error/warn。测试模拟注入已清除，微信真机未验收。
