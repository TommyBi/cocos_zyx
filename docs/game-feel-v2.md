# 连续爆消与动态难度（当前 V5）

## V5：25步轻松段，随后双排加压（2026-11-12）

新局采用规则5，有效横移、引爆和道具等操作每次推进一步；无效拖动、自动掉落与补排不计步。阶段如下：

| 有效操作 | 上升压力 | 其他变化 |
| --- | --- | --- |
| 1–25 | 单排上升 | 100%基础动态辅助，2秒提示，保持连续连消 |
| 26–39 | 每4步双排一次（26、30、34、38） | 大块逐渐增多，辅助与提示渐退 |
| 40–54 | 每2步双排一次（40、42…54） | 更重的大块与上升压力 |
| 55起 | 每步双排 | 所有难度参数封顶，不无限增长 |

普通候选的三格块抽取权重占比从约1/3逐渐到65%（余位不足时截断），行密度仍为5到6格，后期基础辅助15%、有限兜底最大29%、自动提示8秒。临近双排时提前固定并展示两排真实预告，不允许查看预告时重抽；前期只固定下一排，保留根据当前棋盘动态生成的帮助。双排整体升起，不在两排之间掉落或消除；空间不足则整体失败，不做半次上升。每操作自动补排预算仍为5排。

三连及以上，每个成功消除的有效操作都可获得一枚次生炸弹；双排/掉落多排再加一枚。场上最多3枚，操作全部结束后发放；空爆只能续连，不奖励新炸弹。首局最先出现的五枚不同炸弹显示「点我引爆」气泡，账号记录计数，GM重置清除该提示记录；炸弹本体上移4像素，继续规律晃动。

炸弹与受击碎片已恢复正常播放速率：蓄力0.14秒、连锁间隔0.12秒、碎片按原物理时长播放。首枚受击结算等待0.34秒，每枚连锁再加0.12秒，受击块退场后即继续掉落和补排，尾部碎片/烟尘并行播放；不再叠加1.6倍慢镜头。独立输入锁覆盖1.18秒加连锁间隔，逻辑结算与演出锁都结束后才接受新手势，多指情况下已开始的拖拽立即失效，锁定期间的过期移动回调也不能重绘棋盘、中断起爆。每枚起爆同步轻震动与独立合成音效 `sound_bomb_v1.wav`。桌面浏览器无硬件震动能力时由平台适配层自然忽略。

V2/V3/V4冻结长局均保留原结果；客户端要求 `rising-rows-v5`，新局版本固定，服务端按规则重放并检查双排数。schema仍为8、API能力版本8。64个种子×教学/普通两种开局、提示策略：前25步有效横移清行率99.5%/99.7%，多排率25.2%/26.3%；平均堆高约3.9排逐级增加至7.5/7.6排，最终无样本轻松存活到75次横移。重放差异0。这是固定策略模拟，不等于真人胜率或难度倍数。

验证产物：`output/nov12-shop-v5/`、`output/nov12-bomb-v5/`、`output/nov12-difficulty-v5/`。

## 历史V4：更早进入挑战，并减少直接送解

新局使用 `rulesVersion: 4`。第1–9个有效操作为强辅助，第10–14个进阶，第15–20个高手，第21个起固定后期参数。横移、引爆、道具、主动救场都通过同一操作生命周期推进，自动掉落、补排与无效拖动不推进。V2/V3在途局保持原来的横移计数和曲线。

后期基础辅助从35%降为15%；高堆且无炸弹时加8个百分点，连续失误每次加2、最多6个百分点，最大29%。普通排在有界候选中减少自动满行和大量一步消除答案，需要更多规划；辅助排仍提供双排/连锁机会。密度保持5格逐渐过渡到6格：测试发现直接提高到7格会增加自动消除，抵消挑战。自动提示由前期2秒随阶段延后至8秒。三连/双排奖励、场上3炸弹上限及每操作5排预算沿用。

冻结调整前的48步V3记录（2760分、165表情）与之前V2记录做兼容测试。服务端同时支持V2/V3历史重放并核对开局绑定版本；V4客户端要求`difficulty-pressure-v4`能力，数据库仍为schema v8。

同64种子、教学/普通局、提示策略，模拟到60次横移：V3平均结束分数2890/2932，V4为1540/1667；达到3000分从24/64、28/64变为0/64、0/64；存活到60步从63/64、64/64变为31/64、41/64；整体操作满行率从84.1%/84.3%变为64.6%/67.8%。重放差异为0。仅为指定模拟策略对照，不等于真人难度的精确倍数。数据在`output/ui-polish-pressure-v4/`。

## 历史V3：升难速度翻倍（2026-11-11）

新局采用 `rulesVersion: 3`：1–18 次有效横移为强辅助，19–29 次进阶，30–41 次高手，第42次起进入固定的后期难度。基础辅助由100%在第19–42步逐渐下降到35%，随机候选排密度也随同一曲线更早收紧。三连、双排、炸弹、动态兜底与2秒提示保持原设置。

`BoardEngine.resetBoard(seed, tutorial, rulesVersion)`按版本选择曲线，V2在途局仍用36/60/84阈值。服务端核对开局版本与动作头，禁止通过改头切换曲线；新客户端开局前检查`difficulty-ramp-2x`能力。数据库沿用schema v8，不新增字段。修改前冻结的48步V2记录（3550分、177表情）用于历史兼容回归，不能用新曲线重新生成旧预期。

同样64个种子、教学/普通两种开局、提示策略各跑60次横移，V2/V3合计256局。前十步满行率分别保持99.1%/100%，多排占比保持38%/28.6%；整体操作满行率从95.2%/96.3%下降到84.1%/84.3%。重放差异均为0。数据为指定策略模拟，不等于真人难度或失败率翻倍。原始数据在`output/difficulty-ramp-2x/`。

以下为V2设计与历史验证记录，阈值以以上V3说明为准。

本轮完成玩法、双端规则与本地浏览器验收。目标是让友好阶段持续出现普通消除、双排、掉落连锁与次生炸弹，同时保留后续的难度梯度。当前每个表情推进 1%，每百个形成一颗开心豆；总额与其他权益政策沿用当前配置。

## 规则与边界

- 跨操作 combo 最高五倍，每个有效玩家操作最多升级一次。普通操作完全没有满行或爆破会断连；有效引爆保留已有 combo，爆破本身不升级。一次内部的第二次及以后满行演出为“连锁×N”，同时多排显示“N 排齐消”。
- 每段首次达到三连/Good 奖励一枚炸弹，一次完整操作累计至少消两排也奖励一枚。两个来源可叠加，整次操作结束才发放；重复 finish 不会复制奖励。场上最多三枚。
- 炸弹随满行消除、被其他炸弹波及、主动点击均引爆。爆炸按横块几何中心的 3×3 区域移除相交整块；旧炸弹可连锁，重叠范围按块 ID 去重。新生炸弹不在出生操作内继续引爆。
- 自动补排每次操作最多五排，预算用尽即结束本次自动结算。前六次普通移动至少补三层，之后补四层；预算优先于最低层数，不能为凑层数无限补排。
- 阶段仅由有效普通横移推进，普通点击、无效拖动、引爆和补排不推进。1–36 次为连消时刻，37–59 为进阶挑战，60–83 为高手挑战，84 次起为大师挑战且参数不再递增。阶段之间的基础帮助概率连续变化，不随获得炸弹立即跳难。

## 动态生成

生成时使用不消耗真实随机状态的棋盘预测器，按真实重力、满行与炸弹闭包规则模拟。先得到当前稳定盘面，再覆盖最多三个容易识别的移动分支，评估新排落入后是否仍有容易解和多轮消除机会。

候选最多六个普通随机排与 21 个有连续缺口的排（缺口 1–3 格、各合法位置），不做无界搜索。评分考虑短距离答案数量、可清排数、掉落轮次与堆高；多个分支按较差结果与平均结果共同评分。基础帮助概率从前 36 次的 100% 逐渐降至后期 35%；堆高且无炸弹、近期失误可以在有限范围内增加帮助。颜色和表情仍沿用原始概率，不以豆子进度决定是否给好局面。

下一排生成后不会在玩家观察时替换；预测和提示不消费真实随机序列。该实现提供高覆盖率的容易解，不能理解为任意移动都保证消除。

## 碎裂与炸弹演出

碎块使用连续重力轨迹，先向外抛起再下坠，独立旋转并在末段淡出；只绘制一次图形，复用有上限的对象池。炸弹使用独立 `BombEffect.ts` 演出模块，以蔓延火圈和上升的小型蘑菇云表达冲击；不再绘制矩形范围框或网格。受击格子依然由真实 3×3 命中规则高亮，先蓄力、起爆，再扩散并退场。

每枚炸弹的 `affectedPieceIds` 由同一命中规则生成，界面不另猜命中格子。受击宽块整块高亮、出现裂纹、向爆心外反冲并碎裂；重叠爆炸只移除和收集一次。连锁旧炸弹依次起爆，所有本步次生炸弹仍在最终操作结束后发放。表情在格子碎裂时飞出，后续重力等受击格子退场后继续，V5会等待尾部碎片与烟尘完全退场后才继续操作。

范围裁剪、宽块擦边和双炸弹的受击表现，及碎片抛起、回落、淡出与回收的实测记录在 `output/bomb-and-shards/`。本地真实场景可运行 `PLAYWRIGHT_PATH=/absolute/path/to/playwright node scripts/verify-bomb-and-shards.cjs` 复现。

## 代码与版本

- `assets/script/dataModule/BoardEngine.ts`：唯一纯棋盘规则源，包含生成、重力、爆炸、操作生命周期和计分。
- `assets/script/dataModule/ZyxGameModule.ts`：客户端存档、道具库存缓存、账号与结算队列，继承纯规则。
- `assets/script/zyxGame/ZyxGame.ts`：按规则返回的爆炸集合播放动画，最终操作结束时展示次生炸弹及阶段提示。
- `server/src/boardEngine.js`：同源生成的运行产物，禁止手工修改。
- `server/src/replayBoardEngine.js`：V2 事件重放；`gameEngine.js` 按开局版本分流，保留 V1 历史重放。
- `game_rounds.rules_version`：开局持久化，重试和结算不得切换版本；历史对局默认 1。数据库 user_version=7。客户端开局前检查 `adaptive-combo-v2` 能力。

V2 记录 `rules(version=2)`、玩家动作、`settle` 和 `finish`。settle 表示按真实边界执行重力和一次满行结算，finish 才生成次生道具，因此连续补三排后再结算的教学过渡也能精确重现。客户端提交的分数和表情数量需与服务端计算一致。经济领取授权、旧协议收口、账号预算及反自动化仍属于后续经济阶段，不能把本次共享重放视为完整反作弊方案。

修改纯规则后执行：

```sh
npm run sync:engine
npm test
npm run build:web
```

`npm test` 会先检查服务端产物与纯规则源一致。无需在服务端运行 TypeScript 编译器，现有 Docker 构建直接携带已生成 JS。

## 验证结果

客户端 114 项、服务端 22 项测试通过；完整 TypeScript、资源校验、共享产物检查与 Web 构建通过。新增回归覆盖炸弹闭包去重、爆破续连、延迟发道具、存量与补排上限、阶段封顶、只读提示、教学事件边界、版本绑定，以及不同容易解分支的前期体验。

使用 300 种分布式种子，分别模拟教学局和普通局，共 1,400 局：提示策略 600 局、随机容易解 400 局、炸弹优先 200 局、延长至 200 次普通移动的提示策略 200 局。所有完成的操作序列重放差异为 0。

| 策略 / 前十次普通移动 | 教学之后消除率 | 普通局消除率 | 教学之后多排占比 | 普通局多排占比 |
| --- | --- | --- | --- | --- |
| 按提示选解 | 98.9% | 99.5% | 35.8% | 28.2% |
| 在容易解中随机选择 | 98.7% | 99.0% | 24.4% | 20.7% |
| 优先使用炸弹 | 94.7% | 94.5% | 21.9% | 15.1% |

多排占比表示一次完整操作累计清除至少两排，包含同时双排与多轮掉落；实际引爆的体感不完全反映在满行指标中。数据来自指定模拟策略，不是线上或真人新手成功率，也不保证所有合理移动都连续成功。

延长样本按阶段观察，提示策略下每次操作有满行的比例约为 97–99% → 92% → 80% → 72%，平均最高堆高约 3.9 → 4.1 → 4.3 → 4.7 层。后期规则参数封顶不等于每个玩家的棋盘压力绝对不变。

独立无头浏览器全部 API 隔离模拟，正式交互入口跑完三步教学和 18 次后续操作，累计 1,400 分、68 个原始表情块；观察到九次双排/多轮反馈及两枚旧炸弹连锁，重放一致，页面异常为 0。390×844 和 320×568 截图与原始记录位于 `output/game-feel-v2/`。该浏览器操作样本的 39 次出排耗时中位数约 1.5ms、P95 约 4.5ms，属于当前桌面浏览器数据。浏览器验证不代表微信真机帧率和真人手感已验收。
