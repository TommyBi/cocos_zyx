# V12：闪电格、局内道具与续玩

本地候选：`v2026.11.17.01` / 棋盘V12 / API16 / schema11，数据代际保持 `mood_bean_v5_20261112`。用户已通过第二版设计，并补充炸弹与闪电边界。本轮未部署Staging或Production、未上传微信、未提审，也未执行线上资产返还。

## 当前产品规则

- 商城只保留体力（3开心豆/点）和复活卡（25开心豆/张）。仍保留兑换幂等、余额不足引导挑战、体力自然恢复与超上限规则。
- 锤子和魔法棒仅在当前局领取、持有和使用，不再写入跨局库存。图标无持有时角标为「＋」，点开效果与获取弹窗；领取经服务端确认后显示1，并在对应道具上方显示“点击使用”气泡；再点图标选择目标时收起气泡。广告中途退出或网络未确认不显示成功气泡。取消获取或选择保留资格，完整使用才消费持有量。
- 解压锤每局分享领取最多3次，每次1个，用完再领取。弹窗显示剩余领取次数；第三次用完后遮暗，点击提示每局仅可获得3次。
- 魔法棒每局视频领取最多1次。使用后遮暗，点击提示每局仅可获得一次。未完成视频不领次数；网络确认不明保留原领奖ID重试，不重新播放。
- 首次失败使用一次广告复活；再次失败有卡可消费一张复活卡再复活一次；第三次失败直接结算。无卡第二次失败直接结算。每次仍清理顶部8排。已保存的V10/V11局保留绑定版本规则。
- 普通热气球、应急闪电每局分别最多出现4次。按提示出现计次，拒绝或超时仍占次数；共享60秒CD、分数/高度条件与效果不变。某一类用尽后只抽取尚有次数的类型，两类均用尽即停止出现。爱心气球独立，保留原资格、免费和每局一次规则。
- 每累计消除20行生成一个单格闪电块；一次同时消除多行按实际行数累计，拆分本身不计行数。在本次回合完整结算后生成：优先选择幸存普通单格；没有安全宿主时把一个闪电单格预告在下一排，不在静止棋盘上强拆长块制造未结算悬空。新生闪电不参与自己的出生连锁。

## 闪电与爆炸边界

闪电以饱满蓝色块体、连续上沿高光和奶白描边的大号金黄闪电显示，主体标记保持清晰，小电芒循环闪动。消除起手为闪电剪影，不使用独立圆形光片；以蓝色中线与白色亮芯的折线电弧击中最多三个随机幸存长块，显示裂纹，原位变成对应数量的单格，再继续重力与消行。整个过程保持原回合输入锁，演出完成才允许继续拖动。

| 场景 | 规则 |
| --- | --- |
| 满行消除闪电 | 放电一次，后续碎裂和下落继续正常结算 |
| 炸弹或多重连锁波及闪电 | 先完整计算本次爆炸闭包，再对每个被移除的闪电放电；不能因原视图已经炸掉而丢失效果 |
| 两颗以上闪电同批被消除 | 每颗最多选三个当前幸存长块，已经碎成单格的目标不会再入选 |
| 目标在同批爆炸/魔法棒中已消失 | 不作为电弧目标，不复活、不复制该块 |
| 只有一至两个可选长块 | 全部命中；无长块时只结束自身效果，不阻塞回合 |
| 长块带表情或收藏物 | 保留对应位置上的唯一一份，其他碎片不复制奖励；总占格及原颜色保持 |
| 长块带旧炸弹 | 旧炸弹只保留在对应中央单格，不复制成多枚；本次已引爆的炸弹不参与拆分 |
| 连消奖励炸弹 | 宿主选择明确排除闪电；没有普通宿主时沿用安全空位新建普通块，无空位则不发 |
| 暂停、退出或恢复 | 由种子及日志重建特殊块和计数，不把已播放的旧电弧再次作为新逻辑触发 |

随机目标、拆分、唯一ID、生成阈值和两类救场次数均在 `BoardEngine.ts`，服务端通过同源产物重放；界面只读逻辑结果演出。V2–V11旧局的种子序列、旧救场上限与结算结果保留。

## 主线续玩

联网冷启动检测到有效主线残局直接进入局内，不先展示首页或「接着上次继续吧」提示，不重复扣体力。未来其他模式由 `mode` 区分，不应用主线自动续玩。

断网时使用与环境、账号及最近登录令牌匹配的已确认资料缓存和本机有效主线记录继续；仍执行现有7天保存期限与4小时有效局内时长。联网后使用原会话与完整日志核验同步，未结算收益不提前入账。已确认失效的会话会在本机持久化失效标记，重启不能绕过。无有效本机保存、清缓存或换设备仍需联网恢复云端点；核验冲突不会自动丢弃本机尾部。

服务端 `roundTools` 与本机记录保存领取次数、持有资格；棋盘重放恢复已用道具、复活、救场出现次数、消行与闪电生成进度。换局不继承未使用资格。

## 旧道具返还

按用户确认：`返还开心豆 = 3 × (服务端历史锤子库存 + 服务端历史魔法棒库存)`。

schema11在同一迁移事务内入账、清库存、写 `tool_inventory_refunds` 凭据并更新版本标记；重复启动不重复返还。旧客户端后续领取的库存进入V12前也按实际剩余量在开局事务中折算。保留身份、卡片、等级经验、累计获得豆、最高分、体力、旧对局和消费凭据，资产版本递增。退款不作为新的表情经验或游戏所得。`databaseAudit.js` 对迁移前的余额摘要先计入精确应返金额，再验证其他核心字段与历史记录不变。
