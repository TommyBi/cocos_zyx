# 消除游戏服务端

## 经济约束

- `POST /v1/cocos-zyx/games/start` 接收客户端先持久化的 `roundId`，服务端原子扣除 1 点体力并记录入局凭证；相同玩家、相同 `roundId` 的重试不重复扣点。
- 自然体力上限 10，每 5 分钟按服务端时钟恢复 1 点；`bootstrap` 档案与开局响应返回当前体力、下一点恢复时间。
- `POST /v1/cocos-zyx/stamina/share-claim` 接收幂等 `claimId`，按北京时间每天最多领取一次 5 点体力，入账与领取记录同事务可靠落盘，额外奖励可超过自然恢复上限。当前普通微信分享没有可由服务端独立验真的成功凭证，因此该接口只适合尚未关联实物权益的阶段。
- `POST /v1/cocos-zyx/games/settlements` 只接受已在服务端开局的对局。入局后断网的结算可在 7 天内补传；旧版未领取入局凭证的待补传记录会收到 `ROUND_NOT_STARTED`。
- 开心豆和经验沿用现有收集、结算规则。未来活动的实物权益货币不在本版创建或发放。

微信端以服务端用一次性 loginCode 换回的 OpenID 识别账号，客户端不提交可信 OpenID；Web 预览仍使用设备档案。已绑定微信的设备不能省略 loginCode 取回账号令牌。普通分享/广告完成回调尚未接入平台服务端验签，当前虚拟资产约束不能宣称为完整反作弊。

## 结构与迁移

`src/index.js` 提供档案、体力、开局、结算与单局最高分榜；`src/economyConfig.js` 是服务端数值规则；`src/schema.js` 是唯一结构迁移入口。新结构版本为 8，迁移事务和原子落盘成功后才监听端口。

升级会删除秘境两张表、奖励邮件和旧周结算状态，去掉开心豆排行榜字段。保留玩家余额、经验、等级、最高分、历史结算和周最高分，不返还秘境投入。迁移前必须备份生产数据库。`node src/databaseAudit.js backup.sqlite` 可以在内存中演练；加第二个数据库路径可核对实际迁移结果，只输出摘要。

`GET /v1/cocos-zyx/health` 返回 `apiVersion: 8`、`schemaVersion: 8` 和能力列表。未知/已退役路由返回 JSON 404；生产环境不注册调试路由。

发布后从仓库根目录运行 `node scripts/check-cloud.js`，检查真实 HTTPS 的完整客户端协议。它创建独立测试档案，结算 0 分/0 豆，不占排行榜。

## 开心豆商城

当前新开局固定使用 `collectionRule: progress_v2` 与 `rulesVersion: 5`。`difficulty-ramp-2x` 对应18/30/42步的新难度曲线；在途V2局保留原曲线重放。`bean-tool-shop` 能力提供服务端库存、固定20:1道具/5:1体力兑换、道具使用凭据和资产版本；接口及历史迁移见 [商城说明](../docs/shop.md)。普通服务不要配置历史兼容夹具的 `ALLOW_LEGACY_ROUND_STARTS`。

`difficulty-pressure-v4` 对应9/15/21次有效操作的压力曲线，后期基础辅助15%，提示逐渐延后至8秒；V2/V3在途局保留对应原规则。

`rising-rows-v5`：前25步强辅助，26–39每4步双排、40–54隔步双排、55起每步双排并封顶；三连及以上每次有效消除都奖励炸弹。下一排/两排预告固定后不重抽。V2/V3/V4历史重放均保留原结果。

## 2026-11-12 CR订正

跨北京时间日期重试同一个体力领取ID只确认历史结果，不再重复发放或因唯一键500；不会占用新一天领取次数。过期局不得继续使用/领取工具。V5按实际服务端时长限制清屏次数（60秒一档），复活每局一次且固定8排。排行榜采用同分并列名次，与self一致。

`src/resetProgress.js`没有HTTP入口，只能在停止本游戏API并备份数据后执行。`RESET_GAME_GENERATION=mood_bean_v5_20261112 node src/resetProgress.js /app/data/game.sqlite --offline`清空等级、经验、豆、工具、领取/兑换/对局记录并恢复10体力，保留账号、昵称头像、最高分和排行依据；同代际幂等，保留递增资产版本。代码回滚不自动恢复旧数据库。
