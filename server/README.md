# 消除游戏服务端

## 经济约束

- `POST /v1/cocos-zyx/games/start` 接收客户端先持久化的 `roundId`，服务端原子扣除 1 点体力并记录入局凭证；相同玩家、相同 `roundId` 的重试不重复扣点。
- 体力上限 30，每 10 分钟按服务端时钟恢复 1 点；`bootstrap` 档案与开局响应返回当前体力、下一点恢复时间。
- `POST /v1/cocos-zyx/stamina/share-claim` 接收幂等 `claimId`，按北京时间每天最多领取一次 5 点体力，入账与领取记录同事务可靠落盘，不能超过 30 点。当前普通微信分享没有可由服务端独立验真的成功凭证，因此该接口只适合尚未关联实物权益的阶段。
- `POST /v1/cocos-zyx/games/settlements` 只接受已在服务端开局的对局。入局后断网的结算可在 7 天内补传；旧版未领取入局凭证的待补传记录会收到 `ROUND_NOT_STARTED`。
- 开心豆和经验沿用现有收集、结算规则。未来活动的实物权益货币不在本版创建或发放。

目前账号由客户端 `deviceId` 标识，体力约束的是设备档案；实物权益兑换前还需要把档案绑定到可信的微信用户身份。

## 结构与迁移

`src/index.js` 提供档案、体力、开局、结算与单局最高分榜；`src/economyConfig.js` 是服务端数值规则；`src/schema.js` 是唯一结构迁移入口。新结构版本为 2，迁移事务和原子落盘成功后才监听端口。

升级会删除秘境两张表、奖励邮件和旧周结算状态，去掉开心豆排行榜字段。保留玩家余额、经验、等级、最高分、历史结算和周最高分，不返还秘境投入。迁移前必须备份生产数据库。`node src/databaseAudit.js backup.sqlite` 可以在内存中演练；加第二个数据库路径可核对实际迁移结果，只输出摘要。

`GET /v1/cocos-zyx/health` 返回 `apiVersion: 2`、`schemaVersion: 2` 和能力列表。未知/已退役路由返回 JSON 404；生产环境不注册调试路由。

发布后从仓库根目录运行 `node scripts/check-cloud.js`，检查真实 HTTPS 的完整客户端协议。它创建独立测试档案，结算 0 分/0 豆，不占排行榜。
